# รุ่น 18.3.0: รหัสผ่านเริ่มต้นนักศึกษา

บัญชีใหม่และ CSV ใช้รหัสประจำตัวนักศึกษาเป็นรหัสผ่านเริ่มต้น ต้องเปลี่ยนเมื่อเข้าสู่ระบบ โดยรหัสใหม่อย่างน้อย 6 ตัวและต้องไม่ใช่รหัสนักศึกษา อ่าน [คู่มือรหัสผ่าน](STUDENT-PASSWORDS.md) ก่อนอัปเดตฐานข้อมูลเดิม

เอกสารด้านล่างเป็นประวัติรุ่นก่อนหน้า ให้ยึดคู่มือข้างต้นสำหรับนโยบายรหัสผ่านและ migration ปัจจุบัน

# ระบบจองคิวรับหนังสือออนไลน์สำหรับนักศึกษา — Phase 1–9 และ 11–18

## สถานะปัจจุบัน: Feature 2 เสร็จแล้ว (18.2.0)

นักศึกษาและ Admin เปลี่ยนรหัสตนเองได้จากเมนูเปลี่ยนรหัสผ่าน Admin รีเซ็ตรหัสนักศึกษาจากเมนูนักศึกษา โดยยืนยันรหัสปัจจุบันของเจ้าหน้าที่ เพิกถอนเซสชันเก่าของบัญชีที่เปลี่ยนรหัส

อ่าน [คู่มือ Feature 2](FEATURE-2.md), [API](API-FEATURE-2.md) และ [ผลทดสอบ](TEST-RESULTS-FEATURE-2.md) หยุด server เดิมแล้ว npm start ใช้ .env/ฐานเดิม ไม่มี migration หรือ dependency ใหม่ Feature 1 และการจองเดิมยังอยู่ครบ ไม่มี Phase 10 และไม่เริ่มงานถัดไป

ข้อความถัดไปเป็นประวัติการส่งมอบ ให้ยึดคู่มือ Feature 2 สำหรับสถานะรหัสผ่านปัจจุบัน

## บันทึกตอนส่ง Feature 1 (18.1.0)

Admin เพิ่ม/แก้ไขนักศึกษาและนำเข้า CSV ได้จากเมนูนักศึกษา พร้อมเพิ่มกลุ่มเรียน ตรวจไฟล์รายแถวก่อนยืนยัน และป้องกันบัญชีซ้ำ อ่าน [วิธีใช้งาน Feature 1](FEATURE-1.md), [API](API-FEATURE-1.md), [ผลทดสอบ](TEST-RESULTS-FEATURE-1.md) และ [ตัวอย่าง CSV](database/students-template.csv)

หยุด server เดิมด้วย Ctrl+C แล้ว npm start ใช้ .env และฐานเดิม ไม่มี migration/dependency ใหม่ ยังไม่เริ่ม Feature 2 (เปลี่ยน/รีเซ็ตรหัสผ่าน) และ Phase 10 ยังคงถูกตัดออก เอกสารด้านล่างเป็นประวัติราย Phase

## บันทึกตอนส่ง Phase 18

เอกสารสรุปโครงงานครบ 15 หัวข้อ: [เอกสารฉบับสมบูรณ์](FINAL-PROJECT-DOCUMENTATION.md), [พจนานุกรมข้อมูล 11 ตาราง](database/FINAL-DATA-DICTIONARY.md) และ [สรุปส่งมอบ Phase 18](PHASE-18.md) รวมวิธีติดตั้งใหม่ วิธีรัน คู่มือใช้งาน ER Diagram และกรณีทดสอบ

Phase นี้แก้เฉพาะเอกสารและคำอธิบาย config ไม่เปลี่ยนโปรแกรมหรือฐานข้อมูล รุ่นโปรแกรมยัง 17.0.0 ใช้ .env และบัญชีเดิมได้ ไม่ต้อง import/seed/migrate ซ้ำ Phase 10 ถูกตัดออกตามเดิม ไม่มี Phase ถัดไปในขอบเขตปัจจุบัน

เอกสารด้านล่างเป็นบันทึกย้อนหลัง ข้อความ “ยังไม่เริ่ม Phase” และจำนวนตารางในบันทึกเก่าเป็นสถานะ ณ วันส่งมอบครั้งนั้น ให้ยึดเอกสารฉบับสมบูรณ์ด้านบนสำหรับระบบปัจจุบัน

## บันทึกตอนส่ง Phase 17

Final Testing ผ่านทั้ง 6 Scenario ตามข้อกำหนด รวม 192 tests บน MySQL จริง ไม่มี failed/skipped ตรวจ browser ตั้งแต่จองจนถึง Admin อ่านภาพ QR และยืนยันรับ รวมสแกนซ้ำแล้ว

อ่าน [คู่มือ Phase 17](PHASE-17.md) และ [ผลทดสอบ](TEST-RESULTS-PHASE-17.md) ไม่มี migration/dependency ใหม่ หยุด server เดิมแล้ว `npm start` ใช้บัญชีเดิม

Phase 10 ถูกตัดออก และยังไม่เริ่ม Phase 18 เอกสารด้านล่างเป็นบันทึกย้อนหลัง

## บันทึกตอนส่ง Phase 16
ปรับ UI นักศึกษาและ Admin ให้สอดคล้องกัน รองรับ Desktop/Tablet/Mobile หน้าหลักแสดง Welcome, Book Set และสถานะคิว พร้อมปุ่มจองและ My Booking เพิ่มเมนูนักศึกษาแบบอ่านอย่างเดียวและทางเข้ารายการจองโดยตรง

อ่าน [คู่มือ Phase 16](PHASE-16.md) และ [API หน้า Students](API-PHASE-16.md) หยุด server เดิมแล้ว `npm start` ใช้ฐานและบัญชีเดิม ไม่มี migration/dependency ใหม่

ผ่าน 183 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจทั้ง 16 หน้าใน 3 ขนาดจอแล้ว Phase 10 ถูกตัดออก และยังไม่เริ่ม Phase 17

ข้อความด้านล่างเป็นบันทึกย้อนหลัง ให้ยึดคู่มือ Phase 16 สำหรับสถานะปัจจุบัน

## บันทึกตอนส่ง Phase 15
ตรวจ Validation และ Security เพิ่มการตรวจข้อมูลและสิทธิ์หน้า private แก้ตัวนับ login เมื่อส่งพร้อมกัน จำกัด JSON ขนาดเกิน และป้องกันชื่อไฟล์ผิดรูปแบบ/ข้อมูลลับใน error

อ่าน [คู่มือ Phase 15](PHASE-15.md), [การปรับ API](API-PHASE-15.md) และ [รายงานตรวจสอบ](SECURITY-REVIEW.md) หยุด server เดิมแล้วรัน `npm start` ใช้ฐานข้อมูลและบัญชีเดิม ไม่มี migration หรือ dependency ใหม่

ผ่าน 175 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจสิทธิ์ Student/Admin และฟอร์มหนังสือผ่าน browser แล้ว Phase 10 ถูกตัดออก และยังไม่เริ่ม Phase 16

ข้อความด้านล่างเป็นบันทึกย้อนหลัง ให้ยึดคู่มือ Phase 15 สำหรับสถานะปัจจุบัน

## บันทึกตอนส่ง Phase 14
เจ้าหน้าที่เพิ่มประกาศได้จากเมนูประกาศ นักศึกษาเห็นประกาศล่าสุดบนหน้าหลักเมื่อโหลดหน้าใหม่ รองรับภาษาไทยและหลายบรรทัด

อ่าน [คู่มือ Phase 14](PHASE-14.md) และ [API Phase 14](API-PHASE-14.md) หยุด server เดิม รัน `npm run migrate:phase14` แล้ว `npm start` เครื่องนี้เพิ่มตารางสำเร็จแล้ว ไม่ต้อง import/seed ใหม่

ผ่าน 162 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจเผยแพร่และแสดงผลผ่าน browser ทั้ง desktop/mobile แล้ว Phase 10 ถูกตัดออก และยังไม่เริ่ม Phase 15

ข้อความด้านล่างเป็นบันทึกย้อนหลัง ให้ยึดคู่มือ Phase 14 สำหรับสถานะปัจจุบัน

## บันทึกตอนส่ง Phase 13
เจ้าหน้าที่เปิดเมนูรายงาน ดูรายชื่อทั้งหมด รับแล้ว ยังไม่รับ และ No Show แยกสาขา ระดับชั้น ห้อง พร้อมดาวน์โหลด CSV ภาษาไทยตามเงื่อนไขได้ทั้งชุด ไม่จำกัดเฉพาะหน้าปัจจุบัน

อ่าน [คู่มือ Phase 13](PHASE-13.md) และ [API Phase 13](API-PHASE-13.md) เป็นเอกสารปัจจุบัน หยุด server เดิมแล้วรัน `npm start` เปิด http://localhost:3000/admin-reports.html ใช้บัญชีเจ้าหน้าที่เดิม ไม่มี migration หรือ dependency ใหม่ CSV เปิดนำเข้าใน Excel ได้

ผ่าน 151 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจหน้า Report และลิงก์ดาวน์โหลดตรงใน browser แล้ว รวม Desktop/Mobile Phase 10 ยังคงถูกตัดออก และยังไม่เริ่ม Phase 14

ข้อความด้านล่างเป็นบันทึกการส่งมอบก่อนหน้า ให้ยึดคู่มือ Phase 13 สำหรับสถานะปัจจุบัน

## บันทึกตอนส่ง Phase 12

Admin ค้นรายการจองด้วยรหัสนักศึกษา ชื่อ หรือเลขคิว และกรองสาขา ระดับชั้น ห้อง วันนัดรับ และสถานะร่วมกันได้ใน Dashboard เดิม คงเงื่อนไขตอนเปลี่ยนหน้า และล้างกลับทุกรายการได้ ยอดสรุปด้านบนยังเป็นภาพรวมระบบ

อ่าน [คู่มือ Phase 12](PHASE-12.md) และ [API Phase 12](API-PHASE-12.md) เป็นเอกสารปัจจุบัน หยุด server เดิมแล้วรัน `npm start` เปิด http://localhost:3000/dashboard.html ใช้บัญชีเจ้าหน้าที่เดิม ไม่มี migration หรือ dependency ใหม่

ผ่าน 134 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจ browser ค้นชื่อไทยร่วมกับตัวกรอง ผลลัพธ์ว่าง และล้างเงื่อนไขแล้ว รวม Desktop/Mobile Phase 10 ยังคงถูกตัดออก และยังไม่เริ่ม Phase 13

ข้อความด้านล่างเป็นบันทึกการส่งมอบก่อนหน้า ให้ยึดคู่มือ Phase 12 สำหรับสถานะปัจจุบัน

## บันทึกตอนส่ง Phase 11

Admin Dashboard แสดงยอดรายการจองทั้งหมด นัดรับวันนี้ รับแล้ว ยังไม่รับ ยกเลิก และ No Show พร้อมนักศึกษาไม่ซ้ำ แยกตามสาขา ระดับชั้น ห้อง วันนัดรับ และ Book Set แล้วเปิดดูรายชื่อ/รายละเอียดหนังสือได้

อ่าน [คู่มือ Phase 11](PHASE-11.md) และ [API Phase 11](API-PHASE-11.md) เป็นเอกสารปัจจุบัน หยุด server เดิมแล้วรัน `npm start` เปิด http://localhost:3000/dashboard.html ใช้บัญชีเจ้าหน้าที่และฐานเดิม ไม่มี migration หรือ dependency ใหม่

ผ่าน 121 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจ browser เลือกกลุ่ม ดูรายชื่อ และรายละเอียดแล้ว รวม Desktop/Mobile เครื่องมือ Admin เดิมยังอยู่ครบ Phase 10 ถูกตัดออกตาม [Scope](PROJECT-SCOPE.md) และยังไม่เริ่ม Phase 12

ข้อความด้านล่างเป็นบันทึกการส่งมอบก่อนหน้า ให้ยึดคู่มือ Phase 11 สำหรับสถานะปัจจุบัน

## บันทึกตอนส่ง Phase 9

ขอบเขตล่าสุด: [PROJECT-SCOPE.md](PROJECT-SCOPE.md) — ตัด Phase 10: Queue Display ทั้งหมด ไม่สร้างหน้าจอ TV/Monitor, Now Serving, Next Queue หรือหน้าจอเรียกคิวสาธารณะ เจ้าหน้าที่ดูและจัดการสถานะผ่าน Admin Dashboard/Bookings ตามขอบเขตงานเจ้าหน้าที่เดิม

หน้า My Booking แยกคิวปัจจุบันและประวัติ นักศึกษายกเลิกรายการ WAITING ได้ก่อนเวลาเริ่มรอบตามเวลาไทย ระบบคืนคิวว่าง ปิดการใช้ QR เดิม และอนุญาตให้จองใหม่โดยเก็บประวัติไว้

อ่าน [คู่มือ Phase 9](PHASE-9.md) และ [API Phase 9](API-PHASE-9.md) เป็นเอกสารปัจจุบัน หยุด server เดิมแล้วรัน `npm start` เปิด http://localhost:3000/my-booking.html ใช้บัญชีและฐานเดิม ไม่มี migration หรือ dependency ใหม่ใน Phase นี้

ผลทดสอบ: ผ่าน 106 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจ browser ยกเลิก A001 คืนคิว แล้วจองใหม่ A002 และเห็นประวัติแล้ว รวม viewport มือถือ ข้อมูลทดสอบอยู่ในฐานแยก Phase 10 ถูกตัดออกจาก Scope แล้ว Phase ถัดไปคือ Phase 11: Admin Dashboard

ข้อความด้านล่างเป็นประวัติ ให้ยึดคู่มือ Phase 9 สำหรับสถานะปัจจุบัน

## บันทึกตอนส่ง Phase 8

เจ้าหน้าที่สแกน QR ผ่านกล้องหรือไฟล์ภาพ ตรวจรายละเอียดนักศึกษาและหนังสือ แล้วกดยืนยันรับ ระบบบันทึก RECEIVED พร้อม received_at และป้องกันการรับซ้ำ แม้ยืนยันพร้อมกัน ยังไม่เริ่ม Phase 9

อ่าน [คู่มือ Phase 8](PHASE-8.md) และ [API Phase 8](API-PHASE-8.md) เป็นเอกสารปัจจุบัน หยุด server เดิม แล้วรัน `npm ci`, `npm run migrate:phase8`, `npm start` ในโฟลเดอร์นี้ ใช้ `.env` และบัญชีเดิม ไม่ต้อง import schema หรือ seed ซ้ำ เครื่องพัฒนานี้ migrate แล้ว เปิด http://localhost:3000/admin-scanner.html และ Login เจ้าหน้าที่

ผลทดสอบล่าสุด: ผ่าน 94 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจ browser ด้วยภาพ QR จนยืนยันรับและป้องกันรับซ้ำแล้ว รวม viewport มือถือ ยังไม่ได้ทดลองกับกล้องจริงทางกายภาพ

ข้อความด้านล่างเป็นประวัติการส่งแต่ละ Phase ให้ยึดคู่มือ Phase 8 สำหรับสถานะปัจจุบัน

## บันทึกตอนส่ง Phase 7

หน้า “การจองของฉัน” และหน้าจองสำเร็จแสดง QR Code พร้อมเลขคิว วันที่ เวลา และสถานะ ใช้ token สุ่มที่เก็บในฐานข้อมูล ไม่ใส่ข้อมูลส่วนตัวใน QR มีปุ่มบันทึกภาพ PNG และแสดงผลบนหน้าจอมือถือได้

อ่าน [คู่มือ Phase 7](PHASE-7.md) และ [API Phase 7](API-PHASE-7.md) เป็นเอกสารปัจจุบัน Phase นี้เพิ่ม dependency ให้รัน `npm ci` แล้ว `npm start` จากโฟลเดอร์นี้ เปิด http://localhost:3000/my-booking.html และ Login นักศึกษาด้วยบัญชีเดิม ไม่ต้อง import schema หรือ seed ซ้ำ การจองเดิมที่ยังไม่มี token จะได้รับ QR เมื่อเจ้าของเปิดภาพครั้งแรก

ผลทดสอบล่าสุด: ผ่าน 77 tests รวม MySQL จริง ไม่มี failed/skipped ตรวจภาพ PNG โดยถอด QR กลับเป็น token และตรวจ browser ทั้ง desktop กับ viewport มือถือ 390 พิกเซลแล้ว ยังไม่เริ่ม Phase 8 ระบบสแกนของเจ้าหน้าที่

## บันทึกตอนส่ง Phase 6

นักศึกษาเลือกชุดหนังสือที่ตรงกับบัญชี เลือกวันที่/รอบ และยืนยันจองได้จริง ระบบสร้างเลขคิว บันทึกสถานะ WAITING ป้องกันจองชุดเดิมซ้ำและจองเกินความจุ หน้า “การจองของฉัน” อ่านรายละเอียดที่บันทึกไว้ได้หลังรีเฟรช ยังไม่มี QR หรือการยกเลิก

อ่าน [คู่มือ Phase 6](PHASE-6.md) และ [API Phase 6](API-PHASE-6.md) เป็นเอกสารปัจจุบัน ใช้ฐานและบัญชีเดิม ไม่ต้อง import schema หรือ seed ซ้ำ รัน `npm start` แล้ว Login นักศึกษาที่ http://localhost:3000/ ก่อนเปิดเมนูรอบรับหนังสือ เจ้าหน้าที่ต้องเตรียมชุดหนังสือและรอบเปิดในอนาคตก่อน

ผลทดสอบ: ผ่าน 64 tests รวม MySQL จริง ไม่มี failed/skipped และตรวจ flow จองบน browser จริงในฐานทดสอบแยกแล้ว ตั้งแต่ Login จนได้รับ A001 และอ่านรายละเอียดหลังรีเฟรช ไม่มีข้อมูลทดสอบจองเพิ่มในฐานใช้งานจริง

## บันทึกตอนส่ง Phase 5

เจ้าหน้าที่จัดการวัน เวลา ความจุ และเปิด–ปิดรอบรับหนังสือได้ นักศึกษาดูจำนวนจองและคิวคงเหลือ เลือกรอบเพื่อดูข้อมูลได้ แต่ยังไม่มีการยืนยันจองหรือสร้างเลขคิวของ Phase 6

เอกสารปัจจุบัน: [คู่มือ Phase 5](PHASE-5.md) และ [API Phase 5](API-PHASE-5.md) ใช้ schema และบัญชีเดิม ไม่ต้อง import ฐานซ้ำหรือ seed admin ใหม่ รัน `npm start` แล้วเปิด http://localhost:3000/admin-slots.html หรือ http://localhost:3000/booking-slots.html ระบบจะให้ Login ตามบทบาทก่อน

ผลทดสอบล่าสุด: เปิด RUN_MYSQL_TESTS=1 ผ่าน 48 tests ไม่มี failed/skipped รวม Phase 3–5 บน MySQL จริง ข้อมูลรอบในฐานใช้งานจริงยังว่าง ให้เจ้าหน้าที่สร้างรอบเอง ข้อมูลกรณีคิวเต็มอยู่ในฐานทดสอบแยกที่ลบหลังทดสอบจบ

## บันทึกตอนส่ง Phase 4

เจ้าหน้าที่เข้าสู่ระบบเพื่อเพิ่ม แก้ไข ลบ ค้นหาหนังสือ และจัดชุดหนังสือตามสาขา ระดับชั้น ห้อง ภาคเรียน และปีการศึกษา นักศึกษาเห็นเฉพาะชุดที่ตรงกับบัญชีของตน ต่อจากระบบ Login/Profile เดิม ไม่มีการเปลี่ยน schema และยังไม่เริ่ม Phase 5

อ่าน [คู่มือใช้งานและทดสอบ Phase 4](PHASE-4.md) และ [API Phase 4](API-PHASE-4.md) เป็นเอกสารปัจจุบัน

รัน `npm start` ในโฟลเดอร์นี้ แล้วเปิด http://localhost:3000/admin-login.html บัญชีเจ้าหน้าที่ในเครื่องนี้คือ `admin` ใช้รหัสจาก `ADMIN_PASSWORD` ใน `.env` อย่าเผยแพร่ไฟล์นี้ เครื่องใหม่ให้ตั้งค่าและ seed ตามคู่มือ Phase 4

ทดสอบอัตโนมัติผ่าน 34 tests รวม MySQL จริง 26.7.0 และ schema/tests.sql ในฐานทดสอบแยก ตรวจ HTTP Login/Me/รายการหนังสือ/ชุดหนังสือ/Logout ของ admin บนเว็บจริงได้สถานะ 200 ทั้งหมด ฐานใช้งานจริงยังไม่มีหนังสือหรือชุดหนังสือ ต้องเพิ่มผ่านหน้าเจ้าหน้าที่ก่อน

ข้อความด้านล่างเป็นบันทึกตอนส่งแต่ละ Phase ผลทดสอบหรือข้อจำกัดในอดีตไม่ใช่สถานะปัจจุบัน

## หน้าที่ของโค้ด

- HTML แต่ละไฟล์กำหนดชื่อหน้าและ `data-page`
- `assets/app.js` สร้าง UI ด้วยฟังก์ชันแยกหน้า ใช้เมนูและโครงหน้าร่วมกัน พร้อมปุ่มแสดงรหัสผ่านและเมนูมือถือ
- `assets/styles.css` กำหนดสี รูปแบบ และ breakpoint ที่ 1000px และ 700px เพื่อรองรับ desktop, tablet และ mobile
- `backend/server.js` ใช้ HTTP module ที่มากับ Node.js เพื่อเสิร์ฟไฟล์ frontend บนเครื่องเท่านั้น ยังไม่ใช้ Express เพราะ Phase 1 ไม่มี business API
- `database/README.md` สำรองโฟลเดอร์สำหรับ Phase 2 โดยยังไม่มี schema หรือ SQL

## HTTP ใน Phase นี้

ยังไม่มี API ทางธุรกิจหรือ API รับข้อมูลบัญชี มีเพียงการเสิร์ฟไฟล์สาธารณะ:

| Method | Endpoint | Input | Output | หน้าที่ |
| --- | --- | --- | --- | --- |
| GET | / และ URL หน้าเว็บไซต์ด้านบน | ไม่มี body | HTML, status 200 | เปิดหน้า UI |
| GET | /assets/styles.css | ไม่มี | CSS, status 200 | โหลดรูปแบบ |
| GET | /assets/app.js | ไม่มี | JavaScript, status 200 | สร้าง UI |
| HEAD | URL ไฟล์เดียวกับ GET | ไม่มี | Headers ไม่มี body | ตรวจไฟล์ |

ไฟล์ที่ไม่มีจะตอบ 404 และ method อื่นจะตอบ 405 หน้านักศึกษาและเจ้าหน้าที่เปิดได้โดยตรงเพื่อดูตัวอย่าง ยังไม่มี session, token หรือสิทธิ์ผู้ใช้

## วิธีทดสอบและผลที่ควรได้

1. เปิดหน้าแรก: เห็น Login ภาษาไทย และข้อความตัวอย่าง UI
2. กรอกข้อมูลสมมติแล้วกดเข้าสู่ระบบ: แสดงข้อความว่ายังไม่ตรวจสอบบัญชี ไม่ส่งข้อมูล ไม่สร้าง session และล้างช่องรหัสผ่าน
3. กดแสดง/ซ่อน: สลับการมองเห็นรหัสผ่าน
4. กดเข้าชมหน้านักศึกษาตัวอย่าง: ไป Home และเปิดเมนูทั้ง 4 หน้าได้
5. เปิด My Booking: เห็นยังไม่มีการจองและปุ่มจองที่ปิดใช้งาน
6. เปิด Book List และ Profile: เห็นข้อมูลสมมติอย่างชัดเจน
7. เปิด Admin Login และกดเข้าชม: เห็น Dashboard ตัวอย่าง ไม่มีการแก้ไขข้อมูล
8. ปรับหน้าต่างกว้าง 1440, 768 และ 390px: เนื้อหาจัดตามความกว้าง มือถือมีปุ่มเมนู ตารางเลื่อนในกรอบได้
9. ใช้ Tab: เห็นกรอบโฟกัส และใช้ลิงก์ข้ามไปเนื้อหาหลักได้

ตรวจแล้ว: JavaScript syntax ของ frontend/server ผ่าน, สร้าง HTML ทั้ง 7 หน้าผ่านการจำลอง DOM, ลิงก์และไฟล์อ้างอิงภายในมีครบ, handler เมนู/แสดงรหัสผ่าน/ข้อความ login ผ่าน smoke checks และ localhost ตอบ 200

ข้อจำกัดการตรวจ: การจำลอง DOM เป็นเพียง smoke check ยังไม่ได้ทดสอบ layout และการคลิกบนเบราว์เซอร์จริงหรืออุปกรณ์จริง ขั้นตอน 8–9 เป็นรายการตรวจด้วยตนเอง
